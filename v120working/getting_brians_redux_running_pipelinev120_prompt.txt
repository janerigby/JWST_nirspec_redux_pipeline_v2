Work already completed
======================

The script was debugged using real SGAS1429 data. Preserve the existing fixes:

1. Detector1 configuration and det1.run(exposure) were moved inside the
   exposure loop. Previously only the last exposure could run, and some grating
   branches did not run at all.

2. The Detector1 clean_flicker_noise logic was corrected. Medium-grating NRS2
   files skip clean_flicker_noise; other applicable files configure and run it.

3. Shell-based mkdir calls were replaced with os.makedirs(..., exist_ok=True),
   including creation of missing parent directories.

4. FITS files used only for their headers are opened with context managers and
   their headers copied before the files are closed.

5. Searches for nonexistent '*cal2.fits' products were changed to '*cal.fits'.
   The JWST Spec2 pipeline produces *_cal.fits, so the old patterns caused the
   cleaning and Spec3 stages to receive no files.

6. make_offset_file() was fixed. ra_offsets, dec_offsets, and filelist are now
   initialized for every target, and filenames are appended consistently with
   supported grating offsets before the ASDF file is written.

7. run_pipeline() now accepts:

       run_bgsub=True
       cube_resolutions=(0.1, 0.05)

   run_bgsub=False skips do_bgsub_step(), which is necessary while the expected
   background text files are unavailable. cube_resolutions permits running one
   cube scale at a time.

8. A short batch driver was added:

       run_all_IFS_targets.py

   It imports run_pipeline_v1p21_IFS, discovers subdirectories of dir_inputdata
   containing *_uncal.fits, and runs them sequentially with background
   subtraction disabled and cube_resolutions=(0.1,).

Known behavior and limitations
==============================

The JWST clean_flicker_noise implementation emits repeated RuntimeWarnings
about divide-by-zero, overflow, and invalid values in matrix multiplication.
These warnings were nonfatal in successful Detector1 runs.

The 0.05-arcsec Spec3 build was terminated at the native-process level with
exit code 138 (SIGBUS), without a Python traceback. Running it in a fresh
process did not solve the issue. The reliable batch runner therefore requests
only cube_resolutions=(0.1,). Do not claim that 0.05-arcsec cube generation was
validated.

The script intentionally skips medium-grating NRS2 rate files in Spec2, matching
the existing pipeline logic. The tested SGAS1429 cube used the NRS1 products.

Background subtraction has deliberately not been tested and should remain
disabled unless the expected target background text files in dir_bkgfiles are
available.
